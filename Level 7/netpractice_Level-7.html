Subnet Game – Level 7

Goal: connect two departments (dev and accounting) using two routers and three /28 subnets, so that A ↔ C works across the routers and each host uses its router as a default gateway.

1. Core concept of Level 7

There are two small LANs (dev and accounting) and a point-to-point link between two routers. You choose a single mask /28 (255.255.255.240) for all subnets and:

  • Put host A and R11 in one /28 (dev LAN).
  • Put host C and R22 in another /28 (accounting LAN).
  • Put R12 and R21 in a third /28 (backbone between R1 and R2).
  • Use 0.0.0.0/0 as default on hosts and routers so traffic can cross.

2. The three /28 subnets

Subnet 1 – Dev LAN (A + R11) dev

You keep A and R11 together in the first /28 block.

  • R11: 102.198.14.1, mask 255.255.255.240 (/28).
  • A1: 102.198.14.2, mask 255.255.255.240.
Mask /28 → 255.255.255.240 Block size in last octet = 16 Dev subnet: Network : 102.198.14.0 Broadcast : 102.198.14.15 Hosts : 102.198.14.1 – 102.198.14.14

Both R11 and A are in 102.198.14.0/28, so A can use R11 as gateway.

Subnet 3 – Accounting LAN (C + R22) accounting

C and R22 share another /28 for the accounting department.

  • R22: 102.198.14.17, mask 255.255.255.240 (/28).
  • C1: 102.198.14.18, mask 255.255.255.240.
Accounting subnet: Network : 102.198.14.16 Broadcast : 102.198.14.31 Hosts : 102.198.14.17 – 102.198.14.30

Both are in 102.198.14.16/28, so C uses R22 as its gateway.

Subnet 2 – Router link (R12 + R21) backbone

The link between R1 and R2 is a third /28.

  • R12: 102.198.14.254, mask 255.255.255.240 (fixed).
  • R21: 102.198.14.253, mask 255.255.255.240.
Backbone subnet: Network : 102.198.14.240 Broadcast : 102.198.14.255 Hosts : 102.198.14.241 – 102.198.14.254

R12 and R21 sit in 102.198.14.240/28, forming the transit network between the two routers.

Why /28 everywhere? design

A /28 gives 16 addresses (14 usable), which is perfect for:

  • Small LANs with a few hosts.
  • Point-to-point router links.

Using the same mask everywhere makes the address plan easier to explain in the evaluation and avoids wasting addresses.

3. Default routes on hosts and routers

Host routing tables hosts

Each host sends non-local traffic to its own router:

On Host A (dev): 0.0.0.0/0 => 102.198.14.1 (R11) On Host C (accounting): 0.0.0.0/0 => 102.198.14.17 (R22)

So if A or C wants any address outside its /28, it forwards the packet to its default gateway.

Router routing tables routers

Each router knows its directly connected /28s, and uses a default route to reach the other side through the backbone:

On Router R1 (tech.non-real.net): 0.0.0.0/0 => 102.198.14.253 (via R12 → R21) On Router R2 (adm.non-real.net): 0.0.0.0/0 => 102.198.14.254 (via R21 → R12)

So non-local traffic from dev goes to R21, and non-local traffic from accounting goes to R12; each router then routes into its local LANs.

4. End-to-end flows A ↔ C

Forward: A → C (102.198.14.18) flow

A -> C (102.198.14.18) A: 102.198.14.18 not in 102.198.14.0/28 → use default 0.0.0.0/0 → send to 102.198.14.1 (R11) R1: 102.198.14.18 not in dev /28 or backbone /28 → use default 0.0.0.0/0 → send to 102.198.14.253 (R21) R2 (via R21): sees 102.198.14.18 in 102.198.14.16/28 → forward to R22 → deliver to C

The packet leaves dev, crosses the router link, and enters the accounting LAN.

Reverse: C → A (102.198.14.2) flow

C -> A (102.198.14.2) C: 102.198.14.2 not in 102.198.14.16/28 → use default 0.0.0.0/0 → send to 102.198.14.17 (R22) R2: destination not in accounting /28 or backbone /28 → use default 0.0.0.0/0 → send to 102.198.14.254 (R12) R1 (via R12): sees 102.198.14.2 in 102.198.14.0/28 → deliver via R11 to A

The reply uses the symmetric path across the same backbone subnet.

5. Reading the simulator logs

Log pattern logs

forward way : A -> C (102.198.14.18) on A : packet accepted on A: destination does not match any interface. pass through routing table on A : route match 0.0.0.0/0 on A: send to gateway 102.198.14.1 through interface A1 on R1 : packet accepted on R1: destination does not match any interface. pass through routing table on R1 : route match 0.0.0.0/0 on R1: send to gateway 102.198.14.253 through interface R12 on R2 : packet accepted on R2: send to R22 on C : packet accepted on C: destination IP reached

Notice how both A and R1 use their default routes. On the way back, C and R2 do the same in reverse.

How to explain Level 7 in the evaluation oral

“In Level 7 I connect two departments, dev and accounting, using two routers. I choose one mask, /28 (255.255.255.240), for all subnets. I create three /28 networks: 102.198.14.0/28 for dev (R11=.1, A=.2), 102.198.14.240/28 for the router link (R12=.254, R21=.253), and 102.198.14.16/28 for accounting (R22=.17, C=.18).

Each host has a default route to its local router: A to 102.198.14.1 and C to 102.198.14.17. Each router knows its directly connected /28s and has a default route pointing to the other router across the backbone: R1 defaults to 102.198.14.253 and R2 defaults to 102.198.14.254. When A sends to C, the packet goes A → R11 → R12 → R21 → R22 → C. The reply from C follows exactly the reverse path. This setup shows how several small /28 subnets and default routes can connect two departments through a pair of routers.”

Subnet Game – Level 8

Goal: connect home.non-real.com (host D) and office.non-real.com (host C) behind an ISP router, and give both LANs working Internet access using a summarized public block 160.186.60.0/26.

1. Core idea of Level 8

The Internet knows only one summarized route: 160.186.60.0/26 → R1. Inside this /26 you create smaller subnets for:

  • Home LAN (host D + R23),
  • Office LAN (host C + R22),
  • Backbone between R1 and R2 (R13 + R21).

Hosts use default routes to their local router. The ISP router R2 uses a default route to R1. R1 has a specific route for the whole 160.186.60.0/26 block back to R2 and a default route to the Internet.

2. Public block and subnets

Global view – Internet router I summary

Internet only knows the summarized customer block:

On Internet router I: 160.186.60.0/26 => 163.104.250.12 (toward R1)

So any IP from 160.186.60.0 to 160.186.60.63 is sent to R1. Inside that range, you carve three /28 subnets.

Subnet sizes /26 & /28

/26 → 255.255.255.192 Range: 160.186.60.0 – 160.186.60.63 (customer block) Inside that /26, /28s (mask 255.255.255.240) have: 16 addresses, 14 usable hosts per block.

You pick three different /28 blocks inside the /26: one for home, one for office, and one for the R1–R2 backbone.

3. The three /28 subnets

Home LAN – host D + R23 home

  • D1 (fixed mask /28): 160.186.60.1 / 255.255.255.240.
  • R23: 160.186.60.2 / 255.255.255.240.
Home subnet: Network : 160.186.60.0 Broadcast : 160.186.60.15 Hosts : 160.186.60.1 – 160.186.60.14 Gateway for D : 160.186.60.2 (R23)

Host D and R23 share 160.186.60.0/28, so D uses R23 as default gateway.

Office LAN – host C + R22 office

  • C1: 160.186.60.17 / 255.255.255.240.
  • R22: 160.186.60.18 / 255.255.255.240.
Office subnet: Network : 160.186.60.16 Broadcast : 160.186.60.31 Hosts : 160.186.60.17 – 160.186.60.30 Gateway for C : 160.186.60.18 (R22)

Host C and R22 are in 160.186.60.16/28, giving a separate small LAN.

Backbone R1–R2 – R13 + R21 backbone

  • R21: 160.186.60.61 / 255.255.255.240.
  • R13: 160.186.60.62 / 255.255.255.240.
Backbone subnet: Network : 160.186.60.48 Broadcast : 160.186.60.63 Hosts : 160.186.60.49 – 160.186.60.62

This /28 is the transit link between R1 and R2 inside the larger /26 customer block.

Why these ranges fit in /26 consistency

Customer /26: 160.186.60.0 – 160.186.60.63 Chosen /28s: 160.186.60.0/28 (home) 160.186.60.16/28 (office) 160.186.60.48/28 (backbone)

All three /28 networks are subnets of the summarized 160.186.60.0/26, so Internet only needs that one /26 route.

4. Default routes and router configs

Host routing tables hosts

Each host uses a default gateway to reach other networks:

On host D: default => 160.186.60.2 (R23, home router) On host C: 0.0.0.0/0 => 160.186.60.18 (R22, office router)

Meaning: “If destination is not in my /28, send to my router.”

Router R2 – transit.my-isp.org ISP router

R2 has three directly connected networks: home /28, office /28, and backbone /28. For everything else, it sends traffic upstream to R1:

On Router R2: default => 160.186.60.62 (gateway = R13 on R1)

So traffic from C or D going to Internet or to other external networks goes via R13.

Router R1 – gate.non-real.com edge

R1 connects backbone and Internet. It knows:

On Router R1: 160.186.60.0/26 => 160.186.60.61 (toward R2 via R21) 0.0.0.0/0 => 163.104.250.1 (Internet via R12)

The /26 route says “everything in 160.186.60.0–63 is behind R2”. The 0.0.0.0/0 is the classic Internet default.

Internet router I Internet

The Internet doesn’t know the internal /28s. It only knows the summarized /26:

On Internet router I: 160.186.60.0/26 => 163.104.250.12 (toward R1)

So any reply to 160.186.60.x goes to R1, which then uses its /26 route to forward to R2 and finally to C or D.

5. Flow summaries with logs

C ↔ D (office ↔ home) LAN ↔ LAN

C -> D (160.186.60.1) C: destination not in 160.186.60.16/28 → use default => 160.186.60.18 (R22) R2: sees 160.186.60.1 in 160.186.60.0/28 → forward to R23 D: destination IP reached D -> C (160.186.60.17) D: destination not in 160.186.60.0/28 → default => 160.186.60.2 (R23) R2: sees 160.186.60.17 in 160.186.60.16/28 → forward to R22 C: destination IP reached

R2 routes between the two /28 LANs entirely inside the 160.186.60.0/26 block.

C and D ↔ Internet (8.8.8.8) Internet

C -> 8.8.8.8 C -> R22 (default) R2 -> R13 (default to R1) R1 -> 163.104.250.1 (0.0.0.0/0) Internet delivers to 8.8.8.8 8.8.8.8 -> C (160.186.60.17) Internet: 160.186.60.17 ∈ 160.186.60.0/26 → send to 163.104.250.12 (R1) R1: uses 160.186.60.0/26 => 160.186.60.61 (R21 → R2) R2: sees 160.186.60.17 in office /28 → R22 → C
D -> 8.8.8.8 D -> R23 (default) R2 -> R13 (default) R1 -> 163.104.250.1 (Internet) 8.8.8.8 -> D (160.186.60.1) Internet -> R1 using 160.186.60.0/26 R1 -> R21 (R2) using same /26 R2 -> R23 (home /28) D: destination IP reached

Notice: Internet always uses the single /26 route to get back to R1. From there, R1 and R2 know how to reach each /28 inside.

6. How to explain Level 8 in the evaluation

Oral summary exam

“In Level 8 the Internet only knows one summarized route: 160.186.60.0/26 → R1. Inside this /26 I split the block into three /28s: 160.186.60.0/28 for the home LAN (D and R23), 160.186.60.16/28 for the office LAN (C and R22), and 160.186.60.48/28 for the backbone link between R1 and R2 (R13 and R21).

Each host has a default route to its local router: D to 160.186.60.2, C to 160.186.60.18. R2 has a default route to R1 via 160.186.60.62, and R1 has a specific route 160.186.60.0/26 via 160.186.60.61 back to R2 plus a 0.0.0.0/0 default route to the Internet. When C or D sends to the Internet, traffic goes host → local router → R2 → R1 → Internet. Replies come back using the summarized /26 route to R1, then R1 uses the same /26 route to forward to R2, which finally delivers to the correct /28 subnet. The same routing also lets C and D talk to each other through R2.”

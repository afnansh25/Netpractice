Subnet Game – Level 3

Goal: make hosts A, B, and C communicate on the same switch by putting all three in a single /25 subnet and fixing invalid IPs.

1. Core concept of Level 3

All three machines (A, B, C) are plugged into the same switch. That means: one common LAN, one common subnet mask, and IP addresses in the same network. There is still no routing here, only switching.

Initial situation problem

  • A1: 104.198.87.125, mask 255.255.255.0 (editable).
  • B1: 127.168.42.42, mask 255.255.0.0 (editable).
  • C1: IP 104.198.87.282 (invalid > 255), mask fixed to 255.255.255.128 (/25).

So they are in different networks, B uses the 127.x range (loopback-style), and C’s IP is not even valid. Communication obviously fails.

Final configuration solution

  • Common mask for all three: 255.255.255.128 (/25).
  • Keep A1’s fixed IP and adapt everything to its subnet.
Mask /25 → 255.255.255.128 Subnet chosen: 104.198.87.0/25 Network : 104.198.87.0 Broadcast : 104.198.87.127 Usable : 104.198.87.1 → 104.198.87.126 C1 = 104.198.87.124 /25 A1 = 104.198.87.125 /25 (fixed IP, mask changed) B1 = 104.198.87.126 /25

Now A, B, and C are three different hosts in the same /25 subnet 104.198.87.0/25 and can communicate via the switch.

2. Subnet calculation for /25

Finding the correct block subnet math

C1’s mask is fixed to /25, so we must use /25 everywhere. For /25:

Mask: 255.255.255.128 Block size: 128 addresses (in last octet) Last-octet blocks: 0–127 and 128–255 A1 = 104.198.87.125 → in block 0–127 → Subnet is 104.198.87.0/25

That subnet has usable range 104.198.87.1 → 104.198.87.126. We just pick three valid addresses in this range for C, A, and B.

Why 127.x and .282 are wrong invalid

B1 original IP : 127.168.42.42 → 127.x.x.x reserved for loopback testing. C1 original IP : 104.198.87.282 → 282 > 255 → not a valid IPv4 octet.

That’s why we completely change B1 and C1 to clean addresses inside 104.198.87.0/25.

3. Understanding the logs

Example log: A → B logs

forward way : A -> B (104.198.87.126) on A : packet accepted on A: send to A1 on switch S: pass to all connections on C : packet not for me on A : loop detected on B : packet accepted on B: destination IP reached

The switch floods the frame to all ports. C receives it but the IP does not match, so it prints “packet not for me”. A sees its own packet coming back and prints “loop detected”. B recognizes its own IP and prints “destination IP reached”.

How to explain Level 3 in the oral exam oral

“In Level 3 all three hosts are on the same switch, so they must be in a single LAN. The only mask that is fixed is C’s mask 255.255.255.128, which is /25, so I apply /25 to A and B as well. A’s IP 104.198.87.125 is fixed, so it defines the subnet. With /25 the block size is 128, so A belongs to 104.198.87.0/25, with usable range 104.198.87.1 to 104.198.87.126. I choose 104.198.87.124 for C and 104.198.87.126 for B. Now A, B, and C share the same subnet 104.198.87.0/25, and all pairs A–B, A–C, B–C communicate correctly.”

same switch → same LAN mask /25 = 255.255.255.128 block size 128 fix invalid IPs common subnet 104.198.87.0/25

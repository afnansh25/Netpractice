Level 1 – Same Network Rule (Pairs A–B and C–D)

1. What this level teaches

In this level there is no routing. Each pair of hosts must communicate inside a single LAN. The key rule is: two hosts can talk directly only if their IP addresses belong to the same network for the given subnet mask.

2. Left side – Hosts A and B

  • Mask on this link: 255.255.255.0 (this is /24).
  • Network part = first 3 octets, host part = last octet.
  • Chosen network: 104.94.23.0/24.

Network details (A–B):

Network address : 104.94.23.0      (not usable)
Broadcast       : 104.94.23.255    (not usable)
Usable hosts    : 104.94.23.1  → 104.94.23.254

Final configuration:

  • Interface B1 (fixed): 104.94.23.12 / 255.255.255.0
  • Interface A1 (I changed): 104.94.23.13 / 255.255.255.0

Both interfaces are in the same network 104.94.23.0/24. Only the host part (last number) is different, so host A and host B can communicate.

3. Right side – Hosts C and D

  • Mask on this link: 255.255.0.0 (this is /16).
  • Network part = first 2 octets, host part = last 2 octets.
  • Chosen network: 211.191.0.0/16.

Network details (C–D):

Network address : 211.191.0.0        (not usable)
Broadcast       : 211.191.255.255    (not usable)
Usable hosts    : 211.191.0.1  → 211.191.255.254

Final configuration:

  • Interface C1 (fixed): 211.191.222.75 / 255.255.0.0
  • Interface D1 (I changed): 211.191.222.76 / 255.255.0.0

Both interfaces are inside the same /16 network 211.191.0.0/16. The first two octets 211.191 (network part) match, and the last two octets are different hosts, so host C and host D can communicate.

4. How I explain this to the evaluator

“In Level 1 we have two independent LANs and no routing. For A and B the mask is 255.255.255.0 (/24), so the first three octets are the network part. B1 is fixed at 104.94.23.12, so I chose the same network 104.94.23.0/24 and set A1 to another host in the usable range, 104.94.23.13. Both are now in the network 104.94.23.0/24.

For C and D the mask is 255.255.0.0 (/16), so the first two octets are the network part. C1 is fixed at 211.191.222.75, which belongs to the network 211.191.0.0/16, with usable range from 211.191.0.1 to 211.191.255.254. I kept the same network and set D1 to 211.191.222.76. Now C1 and D1 are in the same /16 network and can communicate. The level only checks that each pair shares the same network according to its mask.”

5. Meaning of the logs

forward way : A -> B (104.94.23.12)
on A : packet accepted
on A: send to A1
on B : packet accepted
on B: destination IP reached

The simulator sends a packet from A to B. “Packet accepted” means the IP is valid in the subnet; “destination IP reached” means the communication works. The “reverse way” log repeats the check in the opposite direction (B → A, and similarly for C ↔ D) to confirm bidirectional connectivity.

Level 2 – /27 and /30 Subnets, Loopback Issue

1. What this level teaches

This level still uses the same network rule, but with two different masks: /27 (255.255.255.224) on the left and /30 (255.255.255.252) on the right. It also shows that 127.x.x.x is the loopback range and is not used for normal hosts.

2. Left side – Computers A and B (192.168.29.x, /27)

  • Mask on A1: 255.255.255.224 → this is /27 (fixed).
  • Initial B1 mask was wrong, so I changed it to the same mask: 255.255.255.224.
  • Block size for /27 is 32 in the last octet.

Subnet for A–B:

Last-octet ranges for /27: 0–31, 32–63, ..., 192–223, 224–255
B1 = 192.168.29.222  → in block 192–223

Network address : 192.168.29.192
Broadcast       : 192.168.29.223
Usable hosts    : 192.168.29.193 → 192.168.29.222

Final configuration (A–B):

  • Interface B1 (fixed IP, corrected mask): 192.168.29.222 / 255.255.255.224
  • Interface A1 (I changed): 192.168.29.221 / 255.255.255.224

Both addresses are inside the same subnet 192.168.29.192/27. Only the host part differs, so Computer A and Computer B can communicate.

3. Right side – Computers C and D (/30 and loopback)

  • Mask on C1 and D1: 255.255.255.252 → this is /30.
  • /30 has 4 addresses per subnet, with only 2 usable hosts.
  • The original IPs were 127.0.0.1 and 127.0.0.4, which are in the 127.x.x.x loopback range and not used for real hosts.

Chosen subnet for C–D:

For /30, block size = 4 addresses.

Network address : 126.0.0.0
Broadcast       : 126.0.0.3
Usable hosts    : 126.0.0.1 and 126.0.0.2

Final configuration (C–D):

  • Interface C1 (I changed): 126.0.0.1 / 255.255.255.252
  • Interface D1 (I changed): 126.0.0.2 / 255.255.255.252

Both C1 and D1 are now valid host addresses inside the same subnet 126.0.0.0/30, so Computer C and Computer D can communicate.

4. How I explain this to the evaluator

“On the left side, A1 already uses the mask 255.255.255.224, which is /27, so I copy this correct mask to B1. A /27 subnet has a block size of 32 addresses. The IP 192.168.29.222 on B1 belongs to the subnet 192.168.29.192/27, whose usable host range is from 192.168.29.193 to 192.168.29.222. I choose another address in this range for A1: 192.168.29.221. Now A1 and B1 are in the same network 192.168.29.192/27.

On the right side, the mask is 255.255.255.252 (/30). /30 networks have 4 addresses with only 2 usable hosts. The original addresses are 127.x.x.x, which is the loopback range and should not be used for normal hosts, and C1 and D1 were also in different /30 blocks. I move to a valid subnet 126.0.0.0/30: network 126.0.0.0, usable hosts 126.0.0.1 and 126.0.0.2, and broadcast 126.0.0.3. I assign 126.0.0.1 to C1 and 126.0.0.2 to D1. Now both pairs, A–B and C–D, share a common subnet for their mask, so the communication works in both directions.”

5. Meaning of the logs

forward way : B -> A (192.168.29.221)
on B : packet accepted
on B: send to B1
on A : packet accepted
on A: destination IP reached

The simulator sends a packet from B to A using A’s IP. “Packet accepted” means the address is valid in the subnet; “destination IP reached” means A received it correctly. The “reverse way” lines (A → B, C → D and D → C) confirm that communication works in both directions for each pair.

Level 3 – Three Hosts on One Switch (/25 LAN)

1. What this level teaches

In this level, hosts A, B and C are all connected to the same switch, so they must share a single LAN. That means: same subnet mask and IP addresses in the same network. A new mask appears here: 255.255.255.128 (/25), and we see basic switch behaviour (flooding frames to all ports).

2. Initial situation

  • A1: IP 104.198.87.125, mask 255.255.255.0 (mask editable).
  • B1: IP 127.168.42.42, mask 255.255.0.0 (both editable).
  • C1: IP 104.198.87.282 (invalid, > 255), mask 255.255.255.128 (fixed).

So A, B and C are not in the same subnet, and C even has an invalid IP, so no pair can communicate correctly.

3. My solution

The mask on C1 is fixed to 255.255.255.128 (/25), so I make this the common mask for the whole LAN:

  • A1 mask → changed to 255.255.255.128.
  • B1 mask → changed to 255.255.255.128.

The IP of A1 (104.198.87.125) is fixed, so it defines the subnet. With a /25 mask the block size is 128 addresses in the last octet. This gives: 

Mask /25 → 255.255.255.128
Last-octet blocks: 0–127 and 128–255

A1 = 104.198.87.125 → in block 0–127

Network address : 104.198.87.0
Broadcast       : 104.198.87.127
Usable hosts    : 104.198.87.1 → 104.198.87.126

I then choose valid host addresses inside this range for B and C:

  • C1: 104.198.87.124 / 255.255.255.128
  • A1: 104.198.87.125 / 255.255.255.128 (fixed IP, updated mask)
  • B1: 104.198.87.126 / 255.255.255.128

Now all three interfaces A1, B1 and C1 are in the same subnet 104.198.87.0/25, so every pair of hosts (A–B, A–C, B–C) can communicate through the switch.

4. How I explain this to the evaluator

“In Level 3 all three hosts A, B and C are on a single switch, so they must be placed in one LAN. That means they need the same mask and IPs in the same network. The mask on C1 is fixed to 255.255.255.128, which is /25, so I apply this mask to A1 and B1 as well. The fixed IP of A1 is 104.198.87.125. With a /25 mask the block size is 128, so this IP belongs to the subnet 104.198.87.0/25. In this subnet the network address is 104.198.87.0, the broadcast is 104.198.87.127, and the usable host range is from 104.198.87.1 to 104.198.87.126. I choose 104.198.87.124 for C1 and 104.198.87.126 for B1, both inside this usable range. Now A, B and C all share the same subnet 104.198.87.0/25, so A–B, A–C and B–C all work.”

5. Meaning of the logs and switch behaviour

forward way : A -> B (104.198.87.126)
on A : packet accepted
on A: send to A1
on switch S: pass to all connections
on C : packet not for me
on A : loop detected
on B : packet accepted
on B: destination IP reached

The simulator sends a packet from A to B. “Packet accepted” on A means A is correctly configured. “Switch S: pass to all connections” shows the switch flooding the frame to all its ports. C receives it but the IP does not match its own, so it prints “packet not for me”. A also sees a copy of its own frame coming back and prints “loop detected”, which simply means it discards this echoed frame. B receives the frame with its own IP and prints “destination IP reached”. The reverse-way logs (B → A, A → C, C → A, B → C, C → B) show the same pattern in the opposite direction, confirming bidirectional communication for every pair.

6. Keywords for Level 3

  • Same switch → same LAN → same subnet.
  • Mask /25 = 255.255.255.128, block size 128.
  • Subnet: 104.198.87.0/25, usable hosts 104.198.87.1 to 104.198.87.126.
  • Final IPs: C = .124, A = .125, B = .126.
  • Switch flooding: “pass to all connections”, “packet not for me”, “loop detected”.

Level 4 – Router + Switch in One LAN (/28 choice)

1. What this level teaches

In this level, host A, host B, and router interface R1 are all connected to the same switch. That means they must share one common subnet: same subnet mask and IP addresses in the same network. The goal is to choose a suitable mask, put A, B, and R1 in one LAN, and allow each host to reach the router.

2. Initial situation

  • A1: IP 91.178.115.132, mask 255.255.255.240 (editable).
  • B1: IP 91.178.123.193, mask 255.255.0.0 (editable).
  • R1: IP 91.178.115.91, mask /23 (editable).

The three devices use different masks and B is even in another third octet (123 instead of 115), so they are not in the same network and cannot communicate as one LAN.

3. Why I chose the /28 mask

None of the masks is fixed, so I must choose a single common mask that can contain all three devices in one subnet. I base my choice on A’s IP: 91.178.115.132.

  • We need at least 3 usable host addresses (for A, B, and R1).
  • /30 gives only 2 usable hosts → too small.
  • /29, /28, /27 all have enough hosts, but I want the smallest subnet that still fits comfortably.

For /28 (mask 255.255.255.240), the block size in the last octet is 16. With A’s IP 132: 

Block size for /28 : 16

132 belongs to block 128–143
→ subnet is 91.178.115.128/28

Network address : 91.178.115.128
Broadcast       : 91.178.115.143
Usable hosts    : 91.178.115.129 → 91.178.115.142

This subnet has 14 usable addresses, which is enough for A, B, and R1. It is also a clean block around the fixed value 132, so I decide to use /28 for all three devices.

4. Final configuration

I set the same mask and choose consecutive usable IPs inside 91.178.115.128/28:

  • A1: 91.178.115.132 / 255.255.255.240
  • B1: 91.178.115.131 / 255.255.255.240
  • R1: 91.178.115.130 / 255.255.255.240

Now A, B, and R1 are all in the same LAN with network 91.178.115.128/28. The router interface R1 acts as the gateway for this subnet, so both hosts can reach the router and each other.

5. How I explain this to the evaluator

“In Level 4, host A, host B, and router interface R1 are connected to the same switch, so they must share one subnet. None of the masks is fixed, so I choose a common mask that can contain all three devices. I start from A’s IP, 91.178.115.132. For a /28 mask (255.255.255.240), the block size is 16, so 132 falls in the subnet 91.178.115.128/28, where the network address is 91.178.115.128, the broadcast is 91.178.115.143, and the usable range is from 91.178.115.129 to 91.178.115.142.

I decide to use /28 for all three devices because it is the smallest subnet that easily fits A, B, and R1 in the same block. I set R1 to 91.178.115.130, B1 to 91.178.115.131, and keep A1 as 91.178.115.132, all with mask 255.255.255.240. Now A, B, and the router interface R1 are in the same LAN 91.178.115.128/28, so communication A–B, A–R, and B–R works in both directions.”

6. Meaning of the logs

forward way : A -> B (91.178.115.131)
on A : packet accepted
on A: send to A1
on switch S: pass to all connections
on R : packet not for me
on A : loop detected
on B : packet accepted
on B: destination IP reached

The simulator sends a packet from A to B. “Packet accepted” means A is correctly configured. The switch floods the frame to all its ports (“pass to all connections”). The router sees the frame but the destination IP does not match its own, so it prints “packet not for me”. A receives a copy of its own frame back and prints “loop detected”, meaning it discards it. B receives the frame with its own IP and prints “destination IP reached”, confirming success. The reverse logs for A ↔ R and B ↔ R show the same pattern in the opposite direction: each sender is accepted, sent through the switch, the correct device accepts it, and the others ignore it.

7. Keywords for Level 4

  • Router + hosts on one switch → one LAN / one subnet.
  • Chosen mask: /28 (255.255.255.240).
  • Subnet: 91.178.115.128/28, usable hosts .129–.142.
  • Final IPs: R1 = .130, B = .131, A = .132.
  • Router interface inside the LAN acts as gateway.
  • Switch flooding behaviour: “pass to all connections”, “packet not for me”, “loop detected”.

Level 5 – Two LANs, One Router, Default Routes

1. What this level teaches

In this level, Machine A and Machine B are in two different networks, each connected to a different router interface (R1 and R2). The router connects the two LANs. To make communication work:

  • Each host must share a subnet with the router interface on its side.
  • Each host must have a default route pointing to its router (gateway).

2. Final IP and mask configuration

Left side – Machine A and router R1

  • R1: IP 49.232.179.126, mask 255.255.255.128 (/25).
  • A1: IP 49.232.179.125, mask 255.255.255.128 (/25).

Mask /25 (255.255.255.128) gives a block size of 128 addresses in the last octet. Addresses 0–127 belong to the same subnet: 

Network address : 49.232.179.0
Broadcast       : 49.232.179.127
Usable hosts    : 49.232.179.1 → 49.232.179.126

Both A1 (.125) and R1 (.126) are usable addresses inside 49.232.179.0/25, so Machine A and R1 share the same LAN.

Right side – Machine B and router R2

  • R2: IP 150.188.112.254, mask 255.255.192.0 (/18).
  • B1: IP 150.188.112.253, mask 255.255.192.0 (/18).

Mask /18 (255.255.192.0) has a step of 64 in the third octet. The value 112 lies between 64 and 127, so the subnet is: 

Network address : 150.188.64.0
Broadcast       : 150.188.127.255
Usable hosts    : 150.188.64.1 → 150.188.127.254

Both B1 (.253) and R2 (.254) are usable addresses inside 150.188.64.0/18, so Machine B and R2 share the same LAN.

3. Host routes and the meaning of “default”

Each host has a routing table. When sending to some destination, the host:

  1. Checks if the destination is in its own subnet. If yes → send directly.
  2. If not, it searches the routing table for a matching route.
  3. If nothing specific matches, it uses the default route.

The default route means: “For any unknown network, send packets to this gateway.”

  • On Machine A: default => 49.232.179.126 (gateway = R1).
  • On Machine B: default => 150.188.112.254 (gateway = R2).

So any traffic from A to non-local networks goes to R1, and any traffic from B to non-local networks goes to R2.

4. How the communication works (with logs)

Goal 1 – Machine A ↔ Router

forward way : A -> R (49.232.179.126)
on A : packet accepted
on A: send to A1
on R : packet accepted
on R: destination IP reached

The destination is R1’s IP, which is in A’s subnet 49.232.179.0/25, so A sends directly to R1. The reverse direction (R → A) is also direct in the same subnet.

Goal 2 – Machine B ↔ Router

forward way : B -> R (49.232.179.126)
on B : packet accepted
on B: destination does not match any interface. pass through routing table
on B : route match default
on B: send to gateway 150.188.112.254 through interface B1
on R : packet accepted
on R: destination IP reached

Machine B wants to reach R1’s IP (49.232.179.126), which is not in its local subnet 150.188.64.0/18. The host checks its routing table, matches the default route, and sends the packet to its gateway 150.188.112.254 (R2). The router then delivers the packet internally to R1. The reverse direction is direct from R2 to B1 in the same subnet.

Goal 3 – Machine A ↔ Machine B

forward way : A -> B (150.188.112.253)
on A : packet accepted
on A: destination does not match any interface. pass through routing table
on A : route match default
on A: send to gateway 49.232.179.126 through interface A1
on R : packet accepted
on R: send to R2
on B : packet accepted
on B: destination IP reached

Machine A wants to reach B’s IP, which is not in its local network, so it uses the default route and sends the packet to its gateway 49.232.179.126 (R1). The router sees that 150.188.112.253 belongs to the network 150.188.64.0/18 and forwards the packet out of R2. Machine B receives it in its own LAN. In the reverse direction, B uses its own default route to send traffic to gateway 150.188.112.254 (R2), which then forwards it to A via R1.

5. How I explain Level 5 to the evaluator

“In Level 5, Machine A and Machine B are in two different networks, each connected to a different router interface. I first make each host share a subnet with the router on its side: A1 and R1 are configured in 49.232.179.0/25, and B1 and R2 are configured in 150.188.64.0/18. Then I configure the routing tables. The default route on each host points to its router interface: on A, default goes to 49.232.179.126 (R1); on B, default goes to 150.188.112.254 (R2). When a host wants to reach an address outside its own network, it sends the packet to its default gateway, and the router forwards the packet to the other network. This allows A to reach the router, B to reach the router, and A and B to reach each other through the router.”

6. Keywords for Level 5

  • Two different LANs: 49.232.179.0/25 and 150.188.64.0/18.
  • Router connects the two networks via interfaces R1 and R2.
  • Hosts share subnets with their local router interfaces.
  • default route on host: “send all other networks to this gateway”.
  • Gateway for A: R1 (49.232.179.126); gateway for B: R2 (150.188.112.254).

Level 6 – Web Server, Router, and the Internet

1. What this level teaches

This level connects a local web server to “the Internet”. It introduces: default routes (0.0.0.0/0) on the host and router, and a return route on the Internet router that points back to your public block. The path is: Host A → router R1 → router R2 → Internet router I → Somewhere on the Net, and back.

2. Local LAN: Host A and router R1

  • A1: IP 59.254.83.227, mask 255.255.255.128 (/25).
  • R1: IP 59.254.83.226, mask 255.255.255.128 (/25).

Both A1 and R1 share the same network for mask /25. Conceptually, this is the LAN 59.254.83.x, so Host A can reach R1 directly as its local gateway.

3. Default route on Host A

Host A has the route: 

0.0.0.0/0  => 59.254.83.226

The network 0.0.0.0/0 covers all possible IP addresses. This is the default gateway. It means: “if the destination is not in my local subnet, send the packet to 59.254.83.226 (R1) through A1.”

4. Default route on router R

  • R2: IP 163.172.250.12, mask 255.255.255.240 (connected to Internet router).

Router R uses: 

0.0.0.0/0  => 163.172.250.1

So for any destination not directly on one of its interfaces, R forwards packets toward the Internet via gateway 163.172.250.1 on R2.

5. Internet router route back to your LAN

The Internet router I has a route: 

59.254.83.0/24  => 163.172.250.12

Mask /24 (255.255.255.0) means the whole block 59.254.83.0–59.254.83.255. This tells the Internet that any address in 59.254.83.x is reachable via router R at 163.172.250.12. That includes Host A at 59.254.83.227.

6. End-to-end flow with logs

A -> 8.8.8.8:
  A does not know 8.8.8.8 → matches 0.0.0.0/0 → sends to 59.254.83.226 (R1).
  R does not know 8.8.8.8 → matches 0.0.0.0/0 → sends to 163.172.250.1 (Internet).
  Internet delivers to "Somewhere on the Net".

Reply 8.8.8.8 -> A:
  Internet sees 59.254.83.227 → matches 59.254.83.0/24 → sends to 163.172.250.12 (R2).
  R forwards to R1, then to Host A, which accepts the packet.

7. How I explain Level 6 to the evaluator

“In Level 6, the web server host A and router interface R1 share the same LAN using the mask 255.255.255.128, with A at 59.254.83.227 and R1 at 59.254.83.226. On host A I configure a default route 0.0.0.0/0 pointing to 59.254.83.226, so any destination outside the local subnet is sent to R1. On router R I also configure a default route 0.0.0.0/0 pointing to 163.172.250.1 via R2, which forwards unknown traffic toward the Internet. On the Internet router I, I add a route 59.254.83.0/24 via 163.172.250.12, so replies to any 59.254.83.x address go back through my router. When A sends to an external address like 8.8.8.8, the packet goes A → R1 → R2 → Internet, and the reply uses the 59.254.83.0/24 route to return to A.”

8. Keywords for Level 6

  • Local LAN with gateway: A (59.254.83.227) and R1 (59.254.83.226).
  • Host A default route: 0.0.0.0/0 => 59.254.83.226.
  • Router R default route: 0.0.0.0/0 => 163.172.250.1.
  • Internet router route back: 59.254.83.0/24 => 163.172.250.12.
  • Concept: default route = “send anywhere you don’t know to this gateway”.

Level 7 – Two Departments, Two Routers, Three /28 Subnets

1. What this level teaches

This level connects two different departmental LANs (dev and accounting) using two routers. It shows how to build several small subnets with the same mask (/28), how hosts use default gateways, and how routers forward traffic through an inter-router link.

2. Subnets and final IP configuration

Subnet 1 – Dev LAN (host A + R11)

  • R11: IP 102.198.14.1, mask 255.255.255.240 (/28).
  • A1: IP 102.198.14.2, mask 255.255.255.240 (/28).
/28 → block size 16 in last octet
Dev subnet: 102.198.14.0/28
Network   : 102.198.14.0
Broadcast : 102.198.14.15
Hosts     : 102.198.14.1–14 (A and R11 are here)

Subnet 2 – Inter-router link (R12 + R21)

  • R12: IP 102.198.14.254, mask 255.255.255.240 (/28, fixed IP).
  • R21: IP 102.198.14.253, mask 255.255.255.240 (/28).
Backbone subnet: 102.198.14.240/28
Network   : 102.198.14.240
Broadcast : 102.198.14.255
Hosts     : 102.198.14.241–254 (R21 and R12 are here)

Subnet 3 – Accounting LAN (host C + R22)

  • R22: IP 102.198.14.17, mask 255.255.255.240 (/28).
  • C1: IP 102.198.14.18, mask 255.255.255.240 (/28).
Accounting subnet: 102.198.14.16/28
Network   : 102.198.14.16
Broadcast : 102.198.14.31
Hosts     : 102.198.14.17–30 (C and R22 are here)

3. Host routes (default gateways)

Each host uses a default route to reach other subnets:

  • Host A (dev): 0.0.0.0/0 => 102.198.14.1 (gateway = R11).
  • Host C (accounting): 0.0.0.0/0 => 102.198.14.17 (gateway = R22).

Meaning: “If the destination is not in my local /28 subnet, send packets to my router.”

4. Router routes

Routers know their directly-connected subnets and use default routes for everything else:

  • Router R1 (tech.non-real.net): 0.0.0.0/0 => 102.198.14.253 (via R12 → R21).
  • Router R2 (adm.non-real.net): 0.0.0.0/0 => 102.198.14.254 (via R21 → R12).

So non-local traffic on R1 is sent to R21, and non-local traffic on R2 is sent to R12, across the inter-router subnet 102.198.14.240/28.

5. Flow A → C and C → A (with logs)

A -> C (102.198.14.18)
  A sees C is not in 102.198.14.0/28 → uses default 0.0.0.0/0 → sends to 102.198.14.1 (R11).
  R1 does not have a specific route for accounting → uses its default → sends to 102.198.14.253 (R21).
